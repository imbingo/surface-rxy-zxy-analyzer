# V4.6.5 implementation checkpoints

## Batch 1: provenance and display-isolation baseline

Implemented a read-only `data_scale` module and persistent provenance strip.
Counts distinguish source records, source finite points, theoretical matrix
positions, mapped analysis input, final calculation points, and displayed points.
Unknown source counts remain unknown, not zero or the imported sample size.
Legacy stride can stop early and is deliberately not trusted as a source total.
Known full-scan matrix, Zygo, Precitec and spatial-grid counts are reused.
Column remapping invalidates sampled source validity; full import can count its
finite XYZ after mapping. No extra file scan, changed sampling algorithm, or
measurement definition is introduced in this batch.

Source totals that have not been counted remain unknown. The optional explicit
full-file counting action is not implemented yet. Source-count persistence and
report metadata will be integrated with batch 3.

Added seven tests, including actual GUI display refresh at limits 10000, 30000,
60000 with assertions that metrics and active indices do not change and analysis
is not called. The 1366x768 provenance-strip screenshot was inspected.
