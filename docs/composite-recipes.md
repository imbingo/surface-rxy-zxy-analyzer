# 组合 Recipe 与批量运行

从 V5.0.3 继续开发，随 V5.0.4 发布。此前 VR 长空白前缀修复保留。

## 操作流程

1. 在单层页面处理第一份文件，完成映射、单位、变换、滤波和 ROI；到膜厚或平行度页面点击对应槽的“写入当前数据”。分别处理并写入其他必需槽。
2. 在对应模块“计算与导出”页点击“保存组合 Recipe”。每个槽保存其写入时的完整参数快照；后续修改单层界面不改变已写入槽。旧槽未记录参数时需重新写入，不能用当前界面补齐。
3. 命名配方，明确单片 2 是否参与、文件名关键词、配准方式、结果质量策略、手动删点不兼容策略和 CSV / 报告输出选项，保存到本机 Recipe 库。
4. 从 Recipe 管理加载组合 Recipe，或点击模块中的“运行组合 Recipe / 批量运行”。管理器按“单层 / 膜厚组合 / 平行度组合”分类。
5. 单组运行：按角色双击单元格选择文件。批量运行：选择根目录，每个直接子文件夹为一组，文件夹名默认为样品编号。确认表支持修改编号、勾选参与以及手动更换角色文件。
6. 选择输出位置及本次统一质量策略，点击“开始运行”。进度窗显示当前组、角色、阶段和日志，可取消后续运行。结果表列出状态、指标、单位、质量与警告，可打开独立输出目录。

关键词匹配完整文件名（含后缀），不区分大小写，筛选程序内置及已启用格式扩展支持的后缀。不递归扫描子文件夹内部目录。一个必需角色必须恰好对应一个文件；缺失、多候选、同文件多角色或选中分组间复用文件均不能运行，不按顺序取第一个。手动指定文件可消除识别歧义。无关文件不参与计算。

配方要求单片 2 时始终使用三输入扣减，缺文件或缺快照使该组不就绪；不会自动变成两输入公式。

## 数据结构与计算路径

组合 Recipe 类型为 `SurfaceAnalyzerCompositeRecipe`，`schema_version = 1`。`module` 为 `thickness` 或 `parallelism`；`roles` 内嵌各角色的完整单层 Recipe 副本。旧单层 Recipe 的 schema 1–11 保持原读取能力。未知组合版本、缺失角色、无效参数或不完整快照在更改工作区前拒绝。

```text
父界面：选择组合 Recipe → 确认文件角色 / 统一策略
    ↓ 后台调度，按组串行
每组独立计算进程（独立 QSettings）
    ├─ 角色 A：新单层工作区 → apply_recipe → load_path
    │           → 现有导入 / 映射 / 单位 / 变换 / ROI / 滤波 / 分析
    │           → 与手工写槽相同的快照函数
    ├─ 角色 B：新单层工作区 → 同上（自己的 Recipe）
    └─ 按配方启用角色 C
    ↓ 现有配准 / 组合计算函数
本组结果、报告、追溯元数据 → 完成信号 → 下一组
```

- 使用现有 `SurfaceAnalyzerPro.apply_recipe / load_path / update_analysis`，不使用简化的 CLI 分析接口，不复制另一套单层计算。
- 平行度复用 `_current_parallel_record` 和 `_compute_parallel_result_from_records`；膜厚复用 `_current_gap_record`、`_auto_registration_payload` 和 `_compute_gap_payload`，对实际处理后的点进行匹配扣减。
- 手工与自动膜厚写槽统一使用单层分析实际采用的 `_analysis_z_full`（包含空间高斯后的 Z），解决旧膜厚写槽遗漏处理后 Z 的不一致；扣减、配准、拟合公式不变。
- 手工应用单层 Recipe 原有清空平行度槽的行为仍在；自动执行时，完成的槽保存在组上下文中，不放进下一个角色的工作区，因此不会被清空。每组新建上下文，不借用上一组槽或结果。
- 父界面在运行期间锁定参数与操作，计算在独立进程中完成。后台调度依据进程完成及结果清单推进，轮询只用于进度、超时和取消，不通过模拟点击或固定等待串联业务步骤。
- 本组需要的源列缺失时明确失败，不接受单层自动识别回退到另一个源列来冒充配方映射。设备专用读取和单位语义仍由原有流程执行，同时记录请求参数和实际生效参数。

Recipe 不包含测量点、计算结果或下次必需的历史输入路径。手动删除记录的源哈希保留为兼容性证据；槽中的原 Recipe 名称可追溯，但运行不依赖外部 Recipe 文件。

## 配准、质量和取消

膜厚支持保持原坐标、固定 XY 偏移和每组重新自动匹配，偏移单位 mm，容差沿用当前范围。自动匹配用保存偏移作为初始位置，每组调用现有算法；若算法未接受配准，该组明确失败，不继续冒用旧配准结果。

开始前确定统一策略：

- 抽样 / 估算：默认拒绝；可选择允许并明确标记，原有 `estimated / extrema_preserved / quality` 继续传播，不代表允许产线放行。
- 手动删点：默认源哈希、抽样签名或重放数量不兼容即组失败；可显式选择跳过并记录警告。仍调用原重放检查，不将旧文件点索引直接用于新文件。

某组失败默认继续下一组；取消后当前运行组标记取消，后续组标记未运行。未选中或不就绪的组记录跳过原因。失败、取消、未运行组不写入上一组指标。每组默认时限 1,800 秒，可在运行前设置 10–86,400 秒；超时作为本组失败并继续下一组。Windows 取消会终止本次任务创建的进程树（包括虚拟环境 Python 启动器的计算子进程），不会按进程名称终止其他程序。

输入文件处理前后校验 SHA-256，处理期间变化则失败。运行中不反复弹出质量确认框。计算进程使用独立设置文件，不改用户的最近文件和 Pitch 设置。

## 输出与追溯

每次运行创建 `run_时间_随机标识/`，每组另建带顺序号与样品编号的目录，不覆盖历史结果。

- `composite.recipe.json`：本次实际使用的组合 Recipe（含本次统一策略）。
- `summary.csv`：样品编号、角色文件、配方名称、schema 与应用版本、状态与原因、主要指标及单位、质量、警告、报告与结果路径。
- `batch.json`：所有组的运行状态。
- 各组 `run.json`：实际输入路径 / SHA-256、请求及实际生效的单层参数、重放状态、导入信息、质量标记、配准设置与实际结果、指标及导出路径。
- 各组 `result.csv / report.png`：按配方选项输出。膜厚 CSV 使用现有匹配结果字段及点数据；平行度 CSV 为带单位的指标宽表；报告调用现有模块报告渲染器。
- 各组 `snapshot.npz / snapshot.json`：本次计算的数据槽及结果，用于结果展示；数值数组不使用 pickle，也不写入 Recipe。`worker.log / progress.jsonl` 用于诊断。

汇总在各组完成后及批次结束时更新。只向主界面提交本次最后一个成功运行组的结果；后续实际运行组若失败或取消，则不提交前一组作为当前结果。完整历史结果仍保存在各自输出目录。

## 验证与限制

定向测试见 `tests/test_composite_workflow.py`。覆盖深拷贝、旧槽拒绝、类型及版本、旧单层兼容、两 / 三输入扣减、不同槽参数、文件规则、自动配准重算、连续真实子进程隔离、失败继续、实际取消、超时、质量策略、删点哈希不兼容策略、报告输出、GUI 心跳与结果提交；与现有手工快照逐点 / 逐指标比较。

第一版只做串行及直接子文件夹分组，不含递归、并行或执行中人工配准。每组独立进程有启动开销；未进行生产规模批量吞吐或长期稳定性测试，发布检查另行验证打包后的子进程启动、取消及安装升级链。新增窗口已在本地 Qt 离屏实际渲染检查；尚未进行全部 Windows DPI / 多显示器人工验收。已知完整套件有既有失败及停滞风险，本次仅执行设置总超时的相关定向回归，不无时限运行全量测试。

对于内存数据或由 Gap 计算结果直接写入的槽，手工计算仍可使用，但不能保存为声称“单文件 + 单层 Recipe 可重放”的组合槽。请先导出为独立数据文件，再单层导入并写槽；第一版不支持嵌套组合配方。
