# Keyence VR 长前缀导入修复

基线：GitHub main `c3bad32`（V5.0.3）。开发时保持版本号；用户确认后随 V5.0.4 发布。

## 根因与处理

旧预检将前 400 个物理行 / 512 KB 未发现数字直接当作布局错误，用户指定正文起始行也未参与预检。后续元数据与布局定位又分别受物理行窗口和提前退出影响。因此只放大一个常数不能修复整条链路。

现在预检区分 `passed` 与 `inconclusive`。矩阵样本不完整且未覆盖正文时，进入统一前缀遍历器：逐行读取，空白不消耗非空记录预算，原始物理行号不变。元数据、布局和边界检查均使用该遍历器。手动正文搜索下界参与预检与定位，但仍从文件头扫描校准信息。

预算集中在 `ImportGuardPolicy`：每阶段最多 64 MiB、10 秒、50,000 个非空记录，单行最多 1,048,576 字符，元数据最多保留 2,048 项。手动下界之前不消耗非空记录预算，但仍受字节、时间及单行预算约束。达到预算明确报告“尚不能确认格式错误”及已扫描物理行数，不无限搜索、不全量 readlines。长循环检查取消；搜索状态定期报告物理行数及读取量。

## 矩阵位置语义

- 文件正文前的普通空白作为前缀；正文确定后，内部物理空行保留为全缺测逻辑行。
- 正文内含分隔符的全空记录保留位置，不移除空单元格、空列、NoData，不补零或插值。
- 尾部纯物理空行通常作为文件格式空白；可靠 VR 行数或用户手动行数确认其属于矩阵时，保留相应行。不会凭空生成文件里不存在的行。
- 高度标记之后、第一条有效记录之前的全空分隔记录可能是正文，也可能是分隔带；若数量超过声明矩阵行数则拒绝猜测，要求准确指定正文起始行。若矩阵以纯物理空行开头，应准确指定起始行以保留这些行。
- 可靠列宽优先，避免把真实首列缺测、首行规则 Z 数列误当坐标头。声明矩阵范围内坏行明确失败，不能截断成一个较小的成功矩阵。
- X = 列索引 × Pitch X；Y = (矩阵行数 − 1 − 行索引) × Pitch Y。Pitch、Z 单位和原有 NoData 规则沿用现有实现；Auto 缺少可靠 Pitch 仍需用户补充。

## 旧工具对照

用户确认旧工具为 [`imbingo/vr-data-processing-tool`](https://github.com/imbingo/vr-data-processing-tool/tree/ad21afc98d308371b711c76ab176bf8e4d1caf21)，对照版本 `ad21afc`，对照函数为 `VR数据处理程序.py::_read_keyence_csv`。它先 `readlines()` 整文件，再逐行找数字，因此不受 400 / 50,000 物理行窗口限制；随后的 pandas 默认跳过物理空行，不能直接复用其内部缺测行处理方式。

对该仓库明确标注为模拟测量的 `demo_sample.csv` 及增加 600 行前导空白的副本进行独立对照：两种文件新旧读取均为 220 × 320、29,100 个有效点，Pitch X/Y 47.242 µm，Z 单位 µm。有效位置索引、XY 坐标与源 Z 逐点一致；孔洞位置一致。新工具按文件校准读取 Pitch，对照旧工具采用同一手动 Pitch。未取得用户真实测量样例，不能据此承诺所有 VR 布局均已覆盖。

完整回归与基线差异结果在本次交付说明中列出。所有构造测试均不替代真实设备文件验收。未修改 Excel / XYZ / Pixel / Zygo / Precitec 解析规则、量测公式、滤波或 ROI 定义。
