# V4.6.5 source delivery

## Architecture and unchanged contracts

Old display: each view used array-order linspace sampling. XY used undeleted
base points; detailed views used active_idx. Smart click used the XY sample.
New display: full undeleted XY source -> viewport Raster; active_idx -> spatial
LOD shared by 3D/XZ/YZ. All LOD outputs are original indices. No fake topology,
interpolation, synthetic measurement points or changed measurement formulas.

Rx=atan(b)*1e6, Ry=atan(-a)*1e6. Authoritative PV remains the normal residual range
after first-order best-fit plane removal. Mean Z, TTV, RMS, high-order diagnostic
definitions, filters, ROI, Smart growth, gap, parallelism and adjustment are
unchanged. Display uses the existing raw/high-order residual Z conversion.

XY retains undeleted base overview and the effective ROI gray occupancy layer.
Detailed views retain final active points only. Same-view union/cross-view
intersection and Smart/manual intersection are not changed. Display mode/zoom
does not invoke measurement fitting. A Smart click now searches nearest finite
physical XY across undeleted source candidates, not raster pixels or sampled
points; click-selected seeds can consequently improve versus the old display.

## Raster, density and viewport

build_xy_raster uses finite XY + visible bounds, integer bin IDs and bincount for
counts and Z sums/counts. Both outer edges are included. The mean is masked where
there is no finite Z. Raster extent describes pixel edges in physical mm.
Height uses current visible point min/max, preserving the earlier non-percentile
color behavior. Density uses log1p(count) with explicit display-only labeling.
Missing mode gives empty bins a neutral background. Missing cells are not called
physical holes. Subpixel absence may not be resolved until zoomed in.

Above 50000 XY points, height switches to Raster automatically; density/missing
always use Raster. Resolution uses axes pixel dimensions, capped at 1200/800/600
per side. XY controls and physical axes remain independent of analysis topology.
Reports use the same kernel with bounded axes-based resolution and full overview.

Zoom/pan/resize are debounced 200 ms. A dedicated one-worker executor handles
binning. Only GUI thread updates artists. Source generation, request generation
and exact viewport keys reject stale jobs. At most one running job and one
debounced pending request; two Raster results cached. Full plot updates reset
source/cache, covering import/mapping/transforms/deletion/filter/ROI/Z display.
Source snapshots are owned advanced-index arrays, never modified by workers.

## Spatial LOD and extreme points

Allocate an aspect-aware XY grid within the point budget, select the nearest
source point to each occupied cell center. np.minimum.at finds candidates;
only winners/ties are sorted with deterministic coordinate ordering. Reserve
budget for raw Z max/min and first-order plane residual max/min within active_idx.
The same spatial sample is used for XZ/YZ (the allowed first-version fallback,
not a newly invented cross-section or envelope metric). Orange open circles
mark the required extrema in 3D, preserving true coordinates. Temporary selection
markers retain foreground Line3D behavior and use spatial display subsampling.
Actual output can be below the upper limit. LOD caches retain source references,
input identity, coefficients and limit; source replacement invalidates the cache.

## Provenance and compatibility

Persistent UI separates source valid points, mapped analysis input, final active
count and displayed count/Raster resolution. Source count metadata distinguishes
exact, estimated and unknown; theoretical matrix positions are not valid points.
Known full-scan parsers reuse their counts. Byte-position/early stride totals
stay unknown. Remapping invalidates sampled source validity. No extra full-file
scan is silently added. Optional manual full-source counting is deferred.
Import sampling still limits the coverage visible to Raster: display cannot
recover unimported source data. CSV import trace/report show source validity.

Recipe schema 8 adds optional display.xy_mode and xy_raster_max_side; old
large_file.display_limit retains its role for 3D/detail LOD. Old recipes default
to height/1200; unsupported settings are rejected before applying a Recipe.
Caches/results are not saved. Narrow windows wrap metrics and stack plot cards
vertically in a scroll area; wide windows retain four views.

## Performance evidence

Run `.venv/Scripts/python.exe scripts/benchmark_rendering.py`. Local single-run
timings include tracing overhead; raster 1000x800, zoom bounds -3..3 from -15..15,
LOD cap 30000. These are kernels, not full GUI latency or total process RSS.

| Input | Raster s | Zoom s | LOD s | Raster traced peak MiB | LOD traced peak MiB |
|---|---:|---:|---:|---:|---:|
| 100k | .0152 | .0100 | .0261 | 36.05 | 8.64 |
| 500k | .0386 | .0148 | .1349 | 58.18 | 42.44 |
| 1M | .0707 | .0248 | .3818 | 85.83 | 84.88 |
| 2M | .1221 | .0305 | .7428 | 144.20 | 169.76 |

Input XYZ/index arrays additionally use ~61 MiB at 2M. Final process memory
also includes analysis, DataFrames, Qt/Matplotlib, snapshots and cached images.
No O(N²) algorithm is introduced. Five-million-point benchmarking was optional
and not performed. Full GUI responsiveness is not claimed from kernel timing.
